# Пойдёшь? — Калиновская

Готовая копия сайта для GitHub Pages. Обычные HTML, CSS и JavaScript: сборка, Node.js, npm, серверная часть и ключи API для публикации не нужны.

## Как опубликовать

1. Распакуйте ZIP на компьютере.
2. Создайте на GitHub пустой публичный репозиторий, например `poydesh`.
3. Откройте репозиторий → **Add file → Upload files**. Загрузите **содержимое** папки `poydesh-github-pages`, включая папку `assets`, и сохраните изменения в ветке `main`. Не загружайте сам ZIP. Файл `index.html` должен находиться прямо в корне репозитория, а не во вложенной папке.
4. Проверьте, что файл `.nojekyll` тоже попал в репозиторий. Если проводник скрывает файлы с точкой, создайте его через **Add file → Create new file**: имя `.nojekyll`, содержимое пустое. Этот файл отключает обработку сайта через Jekyll.
5. Перейдите в **Settings → Pages → Build and deployment**. В поле **Source** выберите **Deploy from a branch**, затем ветку **main**, папку **/(root)** и нажмите **Save**.
6. Дождитесь публикации. В **Settings → Pages** появится ссылка **Visit site**.

Адрес будет выглядеть так: `https://ВАШ-ЛОГИН.github.io/poydesh/`. Вместо `poydesh` можно выбрать другое имя репозитория: пути к файлам относительные и работают во вложенной папке GitHub Pages. На первую публикацию может уйти до 10 минут.

Адрес со своим доменом настраивается отдельно в **Settings → Pages → Custom domain**. Файл CNAME намеренно не добавлен: собственный домен не указан.

## Что находится в проекте

| Файл или папка | Назначение |
| --- | --- |
| `index.html` | Страница, шапка, метаданные и доступность |
| `style.css` | Весь дизайн, анимации, адаптация к телефону, светлая и тёмная темы |
| `app.js` | Диалог, ответы, четыре этапа, фотографии, музыка, тема и отправка ссылки |
| `assets/` | Все 6 изображений WebP и музыкальный фрагмент MP3 |
| `concert.ics` | Добавление концерта в календарь |
| `.nojekyll` | Настройка статической публикации GitHub Pages |
| `.gitignore` | Исключение служебных файлов компьютера |
| `SOURCE.txt` | Версия исходного сайта и проверка сохранности файлов |

## Что сохранено

- Дизайн и мобильные стили исходного сайта.
- Анимации, задержка сообщений 1,75 секунды и готовые кнопки ответа.
- Четыре фотографии одним блоком и просмотр фотографий крупно.
- Четыре полоски этапов и оформление шапки.
- Светлая и тёмная темы с сохранением выбора в браузере.
- Первые 37 секунд песни, воспроизведение, пауза и перемотка.
- Ссылка на билеты, календарь, перезапуск и отправка ссылки на прогулку.

Кнопка «Позвать кого-нибудь на прогулку» использует текущий адрес сайта, поэтому после переноса будет отправлять ссылку на GitHub Pages. Билеты продолжают открываться на Qtickets.

Все изображения и аудио находятся внутри проекта. Шрифты системные; внешние CDN, библиотеки и сервисы ChatGPT для работы сайта не нужны.

Текст, даты и музыка перенесены без изменений. Это копия опубликованной версии 12, а не новое редактирование её содержимого.

## Локальная проверка

Можно открыть `index.html` двойным щелчком. Для поведения, близкого к публикации, при установленном Python запустите из папки проекта:

```bash
python3 -m http.server 8000
```

На Windows вместо `python3` можно использовать `py`. Затем откройте `http://localhost:8000/`. Для остановки сервера нажмите Ctrl+C.

Музыка включается нажатием на ▶. Доступность системного меню «Поделиться» зависит от браузера; предусмотрены копирование ссылки и показ ссылки в диалоге.

## Редактирование

- Тексты диалога, кнопки и ссылка на билеты — в `app.js`.
- Шапка, название вкладки и описание для отправки ссылки — в `index.html`.
- Оформление и мобильные правила — в `style.css`.
- Информация для календаря — в `concert.ics`.

При замене изображений сохраняйте имена файлов либо обновляйте ссылки в HTML, CSS и JavaScript. При замене аудиофрагмента обновите его путь в HTML, длительность и границу перемотки в JavaScript.
